# Checklist de entrega no GitHub

O professor pediu um repositório com código-fonte, tarefas em GitHub Projects e histórico de commits de cada integrante.

## Repositório

- [ ] Publicar a **pasta da versão Vanilla** em um repositório do GitHub.
- [ ] Conferir se `README.md` e os arquivos do projeto estão presentes.
- [ ] Confirmar que `node_modules/`, `.env.local` e arquivos sensíveis não foram enviados.
- [ ] Testar `npm install`, `npm test` e `npm run dev` em um novo clone.

## GitHub Projects

Criar um quadro com as colunas **A fazer**, **Em andamento**, **Em revisão** e **Concluído**.

Sugestões de tarefas:

- Layout da página inicial e responsividade.
- Cards dinâmicos e listagem de produtos.
- Busca, filtros e ordenação com arrays.
- Persistência no LocalStorage.
- Cadastro, edição e exclusão de produtos.
- Carrinho, favoritos e pedidos de teste.
- Testes e documentação.

Cada tarefa deve ser atribuída ao integrante que **realmente trabalhou nela**. Vinculem commits/PRs quando possível.

## Histórico

Os commits devem representar alterações verdadeiras do desenvolvimento. Evite inventar autores, datas ou participação que não ocorreu.

## Entrega

- [ ] Link do repositório.
- [ ] Link do quadro no GitHub Projects.
- [ ] Cards com responsáveis e situação atualizada.
- [ ] Histórico de commits individuais verificável.
